# 2026-11-16 물품 인식 오류 진단과 모델 변경

## 문제와 변경

기존 `yolov8n-oiv7.pt`는 제공된 자 사진에서 물체를 찾지 못했고, 가위를 `Knife`로 잘못 탐지했다. 투명 배경 마우스는 알파 채널을 버리면서 배경이 검게 입력되는 별도 문제가 있었다. 서버 중단과는 구별되는 인식 문제다.

- 투명 이미지는 흰색 배경에 합성한다. 불투명 사진과 EXIF 방향 처리는 유지한다. [PR #7](https://github.com/ianianida/ai-team-project/pull/7)에서 수정했다.
- 기본 모델을 `yolov8m-oiv7.pt`로 변경하고 `augment=True`로 TTA를 적용한다. 추가 학습은 하지 않는다.
- 기본 추론 설정은 입력 크기 640, 탐지 임계값 0.25다. 601개 클래스 출력과 기존 Supabase 6종 라벨 매핑을 유지한다.
- `MODEL_NAME`과 `MODEL_TTA`를 환경 변수로 설정하며, `/health`와 `/predict`에서 실제 사용 설정을 확인한다.

## 비교 방법

같은 전처리와 임계값으로 자·가위·투명 마우스 각 1장, 공개 유선·무선 마우스 각 1장을 비교했다. 흰색 빈 이미지 1장을 음성 대조로 사용했다. 등록 라벨 중 가장 점수가 높은 탐지가 정답 라벨과 일치하는지를 확인했으며, 미등록 탐지를 등록 물품으로 강제 연결하지 않았다. 가위 사진의 `Knife` 탐지는 계속 미등록으로 남는다.

환경은 Apple M4, Apple MPS, PyTorch 2.12.0, Ultralytics 8.4.211이다. 시간은 워밍업 후 각 사진의 두 번째 호출에서 측정한 로컬 추론 시간이며, 중앙값은 양성 5장과 빈 이미지 1장을 합쳐 계산했다. 모델 로딩·HTTP 전송·DB 조회 시간은 포함하지 않는다. 반복 측정한 성능 벤치마크는 아니다.

| 모델 | 입력 크기 | TTA | 정답 라벨 연결 / 양성 5장 | 빈 이미지 오탐 없음 | 로컬 시간 중앙값 |
|---|---:|---|---:|---|---:|
| YOLOv8n OIV7 | 640 | 끔 | 3/5 | 확인 | 33.25ms |
| YOLOv8n OIV7 | 960 | 끔 | 1/5 | 확인 | 42.60ms |
| YOLOv8n OIV7 | 1280 | 끔 | 0/5 | 확인 | 57.05ms |
| YOLOv8s OIV7 | 640 | 끔 | 3/5 | 확인 | 31.75ms |
| YOLOv8m OIV7 | 640 | 끔 | 4/5 | 확인 | 64.05ms |
| **YOLOv8m OIV7** | **640** | **켬** | **5/5** | **확인** | **112.00ms** |

입력 크기를 높이는 것만으로는 개선되지 않았다. 이 진단 샘플에서는 medium과 TTA의 조합이 가장 많은 정답 라벨을 반환해 기본값으로 선택했다. TTA는 추론량과 지연을 늘리므로 CPU 실행 시간은 별도 확인해야 한다.

## 선택한 설정의 상세 결과

| 사진 | 연결된 라벨 | 탐지 점수 |
|---|---|---:|
| 제공된 자 | Ruler / 자 | 0.5304 |
| 제공된 가위 | Scissors / 가위 | 0.3748 |
| 제공된 투명 마우스 | Computer mouse / 마우스 | 0.9877 |
| 공개 유선 마우스 | Computer mouse / 마우스 | 0.9867 |
| 공개 무선 마우스 | Computer mouse / 마우스 | 0.9862 |

가위에는 `Knife` 0.3135도 함께 반환됐다. 탐지 점수는 정답 확률이 아니며 관리자의 최종 확인과 직접 선택 기능을 유지한다. 원시 탐지와 시간은 [model-comparison.json](model-comparison.json)에 기록했다. 사용자 제공 사진 자체와 환경 변수·인증키는 저장소에 포함하지 않는다.

실제 FastAPI 서버의 별도 포트에서도 원본 사진 5장을 `/predict`로 전송해 위 라벨과 Supabase의 실제 행 ID 연결을 확인했다. `/labels`는 활성 라벨 6개 모두 모델 지원으로 응답했고 빈 사진은 `no_detection`이었다. 설정 전달·환경 변수 오류·되돌리기와 기존 이미지/DB 계약 테스트를 합쳐 15개가 통과했다. 병합 후 운영 경유 검증 결과는 이 변경의 PR에 추가로 기록한다.

## 한계와 후속 검증

이 5장은 문제 진단과 설정 선택에 사용한 샘플이다. 별도 검증 세트가 아니므로 5/5를 전체 정확도나 실제 촬영 성능으로 해석할 수 없다. 서로 다른 물품 종류는 3종뿐이며, 계산기·스테이플러·우산의 사진 인식은 이 비교에서 확인하지 않았다.

후속 검증은 6종 각각의 실제 촬영 사진을 조명·거리·각도·배경별로 확보하고, 미등록 물품 사진도 포함해 수행한다. 설정 선택에 사용한 사진과 최종 평가 사진을 분리한다. 가위의 낮은 점수와 칼 오탐은 우선 점검 대상이다. 서버 중단 시 인식 실패와 혼동하지 않도록 안내하는 작업은 별도 [이슈 #6](https://github.com/ianianida/ai-team-project/issues/6)에서 관리한다.

## 설정과 되돌리기

```dotenv
MODEL_NAME=yolov8m-oiv7.pt
MODEL_TTA=true
MODEL_IMAGE_SIZE=640
MODEL_CONFIDENCE=0.25
```

`model-server/.env`에 설정하고 서버를 재시작한다. 기존 nano 설정으로 돌아갈 때는 `MODEL_NAME=yolov8n-oiv7.pt`, `MODEL_TTA=false`로 변경한다. 클래스 이름과 ID가 같은 OIV7 계열이므로 DB 마이그레이션과 Vercel 연결 키 변경은 필요하지 않다. 가중치는 Git에 포함하지 않고 첫 실행 시 공식 배포처에서 내려받는다.
